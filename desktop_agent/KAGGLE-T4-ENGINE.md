## 5. 작업별 설계

**A. GPU 샘플링 + 문법 마스크**: 문법이나 사고 예산이 있으면 GPU 샘플링이 꺼진다([sampling.cpp](https://github.com/ggml-org/llama.cpp/blob/b11000/common/sampling.cpp#L415-L424)). GPU에서 온도·top-k·top-p·argmax, 호스트에는 토큰 ID와 수용 판정 확률만. 문법 비트마스크(31KB)는 CPU가 검증 연산과 겹쳐 계산하고 GPU가 적용.

**B. 추측 디코딩 라운드 호스트 왕복 최소화**: 초안 argmax 연속 실행과 수용 판정을 GPU에서, 순환 상태는 위치별 슬롯 선택, 라운드당 동기 1회, 형상별 CUDA Graph. b11000은 Volta 미만만 아키텍처로 CUDA Graph를 끈다([ggml-cuda.cu](https://github.com/ggml-org/llama.cpp/blob/b11000/ggml/src/ggml-cuda/ggml-cuda.cu#L4404-L4415)); 실제 캡처 여부는 계측으로 확인.

**C. SM75 소배치 압축 행렬곱**: 4토큰 검증도 MMVQ 경로([MMVQ_MAX_BATCH_SIZE 8](https://github.com/ggml-org/llama.cpp/blob/b11000/ggml/src/ggml-cuda/mmvq.cuh#L3)). 형식·형상별 대역폭 효율을 측정하고 낮은 것부터 블록·워프 배치, 128비트 적재, 가중치 1회 읽기, 필요 시 무손실 재배열.

**D. Gated DeltaNet 디코드 융합**: 64층 중 48층. 층당 1~2커널로 합치고 검증 위치별 상태를 링 버퍼에 남겨 거절 시 선택.

**E. 긴 문맥 어텐션 디코드**: 192K에서 Q8 KV 6.85GB를 라운드마다 읽음(하한 +21ms). split-K, 커널 내 Q8 역양자화, GQA 24/4 × 4토큰 묶음.

**F. 선택적 TP2**: FFN만 두 GPU에 분할(gate/up 열, down 행), 층당 교환 2회. FFN이 바이트 기준 약 60%라면 라운드당 이론 절약 16~20ms, 교환 128회 비용이 이보다 충분히 작아야 한다.

**G. RAM·디스크 계층 캐시**: 토큰 해시 체인 기반 정확 접두 체크포인트(KV + GDN 상태 + MTP 초안 KV), RAM LRU(바이트 예산), 복원이 재계산보다 빠를 때만 디스크. 앱이 접두를 바꾸면 재사용 불가.

**H. 세션 시작**: 모델·빌드 산출물을 비공개 Kaggle Dataset에 보관하고 SHA 검증 후 로드, 시작 직후 고정 형상 예열.

**I. 비전**: 인코더 비중 측정 후 결정. 같은 이미지 캐시는 과거 반복률이 낮아(41건 중 3건) 후순위.
