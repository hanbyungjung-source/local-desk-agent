# 도구와 기록 계약

2026-09-22 사용자 요청에 따른 공개 동작 중심 설계다. Copilot의 비공개 프롬프트·도구 구현·사고 보존 정책을 복제한 문서가 아니다. 기존 승인·선택 창·좌표·외부 전송 보호를 유지한다.

## 현재 적용

- 모델 호출은 기존 `{"tool":"이름","arguments":{...}}` 구조를 유지한다. 실제 지원 도구의 이름·필수 인자·형식·길이 제한을 프로그램이 생성해 전달한다. 활성화되지 않은 도구나 틀린 인자는 실행하지 않는다.
- 각 도구의 선택 인자 `commentary`는 최대1,200자의 공개 진행 설명이다. 이전 결과에서 확인한 사실·해석의 한계·다음 행동을 사용자 언어로1~3문장 작성하도록 안내한다. 정규화 후 실행 인자에서 제거하고 기존 메시지 필드와 이력에 보존한다. 별도 추론 요청이나 비공개 사고 공개가 아니며 실제 모델이 매번 작성하는지는 별도 검증 대상이다.
- 모델 안내는 응답 형식·권한·관측·좌표 규칙으로 나누고 불러온 그룹에만 첨부·작업 폴더·터미널 절차를 붙인다. 파일 수정은 읽기→해시·원문 확인→수정 결과 확인, 셸은 실행→실행 ID로 출력 조회→종료 상태 확인 순서다. Qwen 27B에도 같은 안내와 허용 도구 JSON 명세를 전달하며 사고 설정·출력 예산·모델 실행 설정은 바꾸지 않는다. 실제 모델의 도구 선택 정확도가 개선됐다는 실측 결과는 아니다.
- 검색 시작 기준은 하나로 통일했다. 아는 경로는 `workspace_read`, 정확한 문자열은 `workspace_search`, 모르는 구현 위치는 `workspace_code_search`, 아는 심볼은 `workspace_symbols`를 선택한다. 허용된 도구의 경로만 안내에 넣고, 수정 권한이 없으면 편집 절차도 생략한다. 데스크톱 도구가 없으면 좌표 안내를 붙이지 않는다. 공통 안전·기록 규칙은 짧은 항목으로 유지하며 실행 스키마와 권한 검사는 바꾸지 않는다.
- 최종 답변과 사용자 질문은 `finish`로 구분한다. 다른 도구 호출은 작업 기록으로 남고 채팅에 도구 이름·실행 중·전달 완료·실패·차단 상태를 표시한다. 전달 완료는 대상 앱에서 작업이 성공했다는 보장이 아니다.
- 도구 인자와 결과는 접어 표시한다. 긴 HTML 모양의 텍스트도 실행하거나 HTML로 렌더링하지 않는다. 표시량을 제한하고 원문은 세션 기록과 페이지 조회로 보존한다. 전체 복사는 원문을 사용한다.
- 브라우저 검색은 Google로 이동하고 HTTP403/429·비정상 트래픽·CAPTCHA·동의 화면·접속 실패를 감지하면 Bing으로 한 번만 전환한다. 같은 브라우저에서는 이후 Bing을 사용한다. `search`에 실제 엔진·상태·시도별 URL/HTTP 상태/사유를 기록하며 양쪽 실패는 빈 결과와 오류로 반환한다. 브라우저 관측은 제목·URL·본문 텍스트·화면에 보이는 제어 요소로 구성한다. 검색 엔진의 동의 화면·보안 확인을 우회하지 않는다. 검색어는 전환 시 대체 검색엔진에도 전송된다.
- 최신 도구 캡처 한 장은 새 캡처가 성공할 때까지 같은 세션의 모델 입력에 다시 포함한다. 캡처 원본과 출처 이벤트·촬영 시각은 기록에 남는다. 과거 이미지 전체를 매 요청에 넣지는 않는다. 일반 도구 결과·실패로 최신 사진을 지우지 않는다.
- 재시작 후에는 해당 세션의 등록된 최신 캡처만 복원한다. 권한이 꺼졌거나 파일이 없거나 세션 밖을 가리키면 재첨부하지 않는다. 이전 이미지를 현재 화면이라고 주장하지 않으며, 좌표 입력은 원래 창 식별자·경계 검사를 계속 거친다. 기록 편집·재실행·삭제로 이벤트가 사라지면 그 이벤트를 다시 선택하지 않는다.
- 모델이 반환한 사고 텍스트는 응답 메타데이터로 보존하고 접어 표시한다. 다음 요청의 일반 대화에 자동 재주입하지 않는다. 내부적으로 반환되지 않은 사고 토큰은 조회하거나 복원할 수 없다. 긴 작업의 연속성은 확인된 도구 결과·상태·사용자가 볼 수 있는 요약으로 유지한다.
- 이미지 재첨부는 외부 API에서 전송량·요금과 로컬에서 입력 처리 비용을 늘릴 수 있다. 제공자별 이미지 문맥 캐시 적중을 보장하지 않는다. 외부 API 동의 범위에는 보존 캡처도 포함된다.

## 캐시와 문맥 압축

고정 시스템 가이드는 앞에 유지하며 실시간 상태·이미지는 뒤에 둔다. 같은 세션에서는 허용된 기존 로드 그룹을 복원한다. 로컬 `cache_prompt=true`와 서버 보고 재사용 토큰·가이드 해시를 기록한다. 보고가 없으면 0으로 채우지 않는다. 캐시 수치는 전체 입력 재사용 보고이지 가이드의 정확한 토큰 경계까지 검증한 값은 아니다. 운영 슬롯 KV와 별도 RAM 프롬프트 캐시는 다른 기능이다.

2026-09-23 단순 가이드 판단 검사에서 실제27B가 알려진 경로 읽기·심볼 정의 검색·모르는 위치의 코드 검색·꺼진 셸 실행 대신 안내의4개 사례를 각각1회 통과했다. 도구 실행은0회이고, 세 도구 선택에 한국어 공개 설명이 포함됐다. 후속3요청은 가이드 해시가 같고 입력2,424~2,441토큰 중2,375토큰 재사용이 보고됐다. [검사 원자료](data/maintenance/guide-routing-20260923-v1/result.json)에 응답과 사용량을 보존한다. 사고 모드는 기존 설정을 따랐으며 가장 긴 사례는약80.3초였다. 실제 파일 작업·자동 요약 품질·다중 도구 연쇄 정확도 또는 이전 버전 대비 속도 개선을 입증한 검사가 아니다. 같은 검사를 반복 측정하지 않았다.

자동 압축은 여유 예산85%에서 기존 제외 후보를 찾아 현재 요청·최근6개 이벤트·진행 중 호출을 빼고 요약한다. 같은 모델·가이드 접두부와 요약 전용 지시를 사용하며 허용 출력은 `finish`뿐이다. 요약에는 목표·제약·확인한 결과·기록/호출 ID·변경 파일·검사·실패·금지된 재시도·미완료 작업을 보존하도록 요청한다. 도구 실행과 이미지는 전달하지 않고 비공개 사고 메타데이터도 요약 입력에 넣지 않는다. 일부 긴 기록은 기존 구조화된 미리보기를 사용하므로 요약은 원문을 완벽히 대체하지 않는다.

요약은 최대3,500자로 검사하고 원문 해시·대상 ID와 함께 별도 표에 저장한다. 원문은 유지하며 요약을 일반 사용자 권한이나 새 지시로 승격하지 않는다. 원문 변경·삭제·재실행 후 해시가 맞지 않으면 무효화한다. 요청당 시도 최대2회, 첫 실패 후 같은 작업에서는 반복하지 않는다. 요약 결과가 문맥을 줄이지 않거나 현재 요청·최근 기록을 보존할 수 없으면 적용하지 않는다. 실패·불충분한 공간에서는 기존 제외 정책으로 계속할 수 있고 제외·요약 범위를 기록한다. 요약도 기존 모델 시간·메모리·취소 보호를 따르고 추가 요금·지연·요약 이후 KV 재계산이 발생할 수 있다.

## 코드 검색과 참조

`workspace_code_search(query,path,limit)`는 SQLite FTS5 BM25와 분리한 식별자 단어를 이용한 로컬 검색 기반 RAG다. `workspace_symbols(query,path,kind,limit)`는 Tree-sitter 정의 및 정확한 이름의 구문상 참조를 반환한다. 임베딩 벡터 모델·LSP 의미 해석·원격 색인은 사용하지 않는다. Python, JavaScript/JSX, TypeScript/TSX, C/C++, C#, Java, Go, Rust를 분석하며 구문 오류 여부를 표시한다. 다른 지원 텍스트는 코드 조각 검색만 한다.

색인은 세션 아티팩트 `code-index/<루트해시>.sqlite3`에 보관한다. 각 검색 전 범위를 재검사하고 파일 해시가 바뀐 경우 갱신한다. `.gitignore` 중첩 규칙과 알려진 생성 폴더·보호 경로·링크 배제를 적용한다. 결과 반환 전 실제 파일을 다시 읽어 해시를 대조한다. 한 번 갱신 최대60초·10만 파일·512MiB·새 코드 조각10만 개, 색인 대상 파일은2MiB 이하로 제한한다. 한도나 누락이 있으면 `index_complete`·`skipped_files`를 확인하고 범위를 좁힌다. 일반 `workspace_read`의16MiB 한도와 별개다. 취소 후 부분 색인은 다음 호출에서 재검사하며 모든 프로젝트·언어를 완전히 분석했다고 주장하지 않는다.

결과의 `read_ref`를 따라 원문을 확인하고, 편집에는 새로 읽은 SHA256을 사용한다. 한국어 자연어와 영문 코드가 어휘상 겹치지 않으면 의미 검색처럼 찾지 못할 수 있으므로 관련 영문 식별자나 문자 검색을 함께 사용한다. 검색 결과·주석·README는 신뢰되지 않은 자료이고 지시가 아니다. 코드 색인 자체는 로컬이지만 외부 API에 선택 결과가 전달될 수 있다. 색인 파일은 세션 삭제 시 함께 지워지며 별도 자동 만료는 없다.

공개 참고: [VS Code 작업 공간 검색](https://code.visualstudio.com/docs/agents/reference/workspace-context), [대화 문맥 압축](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions#_compact-conversation-context). 이는 공개 동작을 참고한 별도 구현이며 Copilot 내부 구현의 복제가 아니다.

## 호출과 결과 이력

새 호출에는 프로그램이 `call_id`를 부여하고 호출·결과·지연 완료 알림에 보존한다. 모델이 ID를 만들거나 응답 형식에 덧붙일 필요는 없다. 백그라운드 결과를 별도 호출로 조회하면 조회 호출 ID와 시작 호출의 `origin_call_id`를 모두 남긴다. 셸 시작·종료와 파일 변경 알림도 원래 호출에 연결한다. 기존 기록은 원본을 수정하지 않으며 도구·작업 ID로 확실히 연결되는 경우만 표시용 연결을 만든다. 같은 이름의 미완료 호출이 여러 개이면 추측하지 않는다.

모델 이력은 `kind=tool_call / tool_result / tool_update`, `call_id`, 도구와 인자, `execution_status`, `summary`, `result`, `raw_ref`로 구분한다. 결과에도 원래 호출의 도구·인자 미리보기와 원문 위치가 남으므로 문맥에서 앞선 호출이 제외돼도 식별할 수 있다. `status=delivered`는 결과를 받았다는 뜻이고 실제 상태는 `execution_status`로 확인한다. `returned`는 관측/반환 완료, `applied`는 파일 변경 적용, 셸의 `completed`·종료 코드0은 프로세스의 정상 종료이며 사용자 목표 달성을 자동 보증하지 않는다.

`summary`는 저장된 반환 값에서 경로·해시·종료 코드·출력 크기·결과 개수·오류 등을 추출한다. 별도 LLM이 의미를 추측해 요약하지 않는다. 긴 본문은 앞뒤를 남기고, 큰 목록은 일부와 전체 개수를 표시한다. `excerpt`는 생략 표시이지 빈 결과나 성공 표시가 아니다. 전체 호출 인자와 결과 원문은 세션 기록에 그대로 보존한다.

`raw_ref`의 `session_record` 도구는 현재 세션의 `event_id`를 직접 조회한다. `offset`과 `next_offset`은 문자 단위이며 페이지당 최대64,000자다. 첨부·기록 그룹이 아직 로드되지 않았다면 먼저 `files` 그룹을 불러오고 사용자 권한을 따른다. 원문을 되찾기 위해 파일 수정이나 셸 실행을 반복하지 않는다. 큰 페이지가 문맥에 들어가지 않으면 더 작은 `limit`을 사용한다. 기존 `session_history` 전체 로그 조회도 유지한다.

채팅은 같은 연결 정보를 이용해 호출 ID·실행 상태·최근 상태 이력·핵심 결과를 접어 표시하고 원문 보기를 제공한다. 외부 OpenAI native-tools 전송은 ID가 맞는 완결된 호출·결과 쌍만 전용 메시지로 바꾼다. 순서가 교차하거나 확실하지 않은 기록은 ID를 포함한 텍스트로 유지해 잘못된 쌍을 만들지 않는다. 로컬 27B는 구조화된 JSON 이력을 받으며 실제 응답 정확도 향상은 별도 측정 대상이다.

## 파일과 PowerShell 도구

2026-09-23 후속 구현 승인에 따라 아래 도구를 연결했다. **새 도구의 기본값은 사용 안 함**이다. `도구 선택` 창에서 작업 폴더와 도구별 `사용 안 함 / 매번 확인 / 허용`을 저장한다. 그룹을 선택해 함께 변경하거나 이름·설명으로 검색할 수 있다. 목록 로드는 권한을 부여하지 않으며 직접 호출·중첩 작업에서도 실행 권한을 다시 검사한다. 기존 화면·입력·브라우저 권한은 추가 제한으로 유지된다. `finish`와 그룹 명세 로드는 내부 필수 기능이다.

파일 수정과 셸 실행은 `허용`으로 설정해도 매번 확인한다. 민감 작업 확인과 비밀번호 입력 차단도 해제되지 않는다. `terminal_start`를 켤 때 출력 조회와 중단 도구도 함께 켜야 한다. 승인 취소는 현재 작업을 중단한다.

| 도구 | 입력 | 결과와 사용자 표시 | 보호 |
|---|---|---|---|
| `workspace_read` | 승인된 루트 안의 경로·행 범위 | 경로·실제 읽은 범위·내용·버전 해시 | 민감 경로와 루트 밖 경로 거부 |
| `workspace_search` | 일반 문자열·대상 폴더·결과 한도 | 파일·행·제한 여부 | 대소문자 무시, 정규식 아님, 승인된 루트만 |
| `workspace_apply_patch` | 경로·`expected_sha256`·`old_text`·`new_text` | 변경 차이·원본/결과·새 해시 | 줄바꿈 포함 정확히 한 번 일치하는 블록 교체, 승인 뒤 충돌 검사 |
| `terminal_start` | 작업 폴더·PowerShell 명령·제한 시간 | 실행 ID·PID와 시작 시각·명령·출력 파일 | 명령과 작업 폴더를 먼저 표시하고 승인, 관리자 권한 자동 상승 금지 |
| `terminal_output` | 실행 ID·출력 위치·한도 | stdout/stderr 페이지·진행 상태·종료 코드 | 해당 세션의 소유 실행만 조회 |
| `terminal_stop` | 실행 ID | 중단 요청·종료 상태 | PID를 받아 종료하지 않고 해당 실행의 Windows 작업 개체 핸들만 사용 |

기존 파일은 기대 SHA256이 일치해야 한다. 새 파일은 해시와 `old_text`를 빈 문자열로 주고 존재하는 상위 폴더를 사용한다. 파일 삭제·폴더 생성·일반 unified diff 적용 도구는 아니다. UTF-8과 원래 줄바꿈을 보존한다. 기존 파일 교체는 임시 파일과 원자적 이름 교체를 사용하고, 새 파일은 배타적으로 생성한다. 적용은 테스트 통과를 의미하지 않으며 ACL·동시 외부 변경을 완전히 격리하는 파일 시스템 샌드박스는 아니다.

### 기록과 화면

`터미널 / 변경 파일` 창에서 현재 세션의 명령·작업 폴더·PID·출력·상태·종료 코드를 조회하고 소유 실행을 중단한다. 출력은 페이지 조회와 최신 부분 보기를 지원한다. 파일 탭은 전체 변경 차이, 원본, 변경 후 내용과 현재 파일의 읽기 전용 보기를 제공한다. 파일을 연다고 스크립트가 실행되지는 않는다. 승인 창은 긴 내용을 잘라 보여 주되 전체 보기 버튼으로 원문을 확인할 수 있다.

세션 아티팩트의 `terminals/<실행ID>.json` 및 `.log`, `file-changes/<변경ID>/{change.json,change.diff,before.txt,after.txt}`에 보관한다. 새 파일에는 원본이 없다. 앱 재시작 후 과거 출력은 읽을 수 있지만 과거 PID를 재사용해 종료하지 않는다. 종료 상태가 기록되지 않은 실행은 `unknown_after_restart`이며 성공으로 간주하지 않는다. 기록은 자동 정리하지 않으므로 디스크 사용량은 누적될 수 있다.

### 넉넉한 실행 한도

| 항목 | 한도 |
|---|---|
| 파일 | UTF-8 파일 16MiB, 읽기 한 번 2,000행·64,000자 |
| 검색 | 60초, 파일 100,000개, 폴더 20,000개, 읽은 내용 512MiB, 결과 최대 1,000개 |
| 수정 | 이전/새 블록 각각 256,000자, 생성된 변경 차이 8MiB |
| PowerShell | 기본 600초·최대 3,600초, 세션 동시 실행 8개 |
| 출력 | 실행당 64MiB 저장, 도구 조회 한 번 최대 64,000바이트 |
| 화면 | 원문을 유지하고 미리보기·페이지는 주로 12,000자씩 표시 |

한도 도달은 명시적인 잘림·오류·`output_limit` 상태로 반환한다. 앱의 별도 작업 단계·전체 작업 시간 설정과 모델 요청 제한은 그대로 적용되며, 작업 종료·중단·앱 종료 시 남은 셸 실행을 취소한다. 셸 도구의 최대 60분이 작업 전체 제한을 자동으로 늘리지는 않는다.

### 보호와 한계

파일 도구는 상대 경로만 받고 상위 경로 탈출·대체 데이터 스트림·예약 장치명·심볼릭 링크·정션·공유 하드링크·앱 데이터·알려진 자격 증명 경로를 거부한다. 읽기 전용 파일은 수정하지 않는다. G로 옮긴 연구 정션과 공유 원자료도 직접 수정하지 않는다. 파일 이름만으로 모든 비밀을 알아낼 수는 없다.

PowerShell은 **사용자 권한의 일반 셸이며 샌드박스가 아니다.** 작업 폴더 밖의 파일·네트워크·설치·삭제에도 영향을 줄 수 있으므로 명령 전체를 확인해야 한다. 관리자 앱에서 셸 실행을 거부하고 명백한 권한 상승·비밀 입력 명령을 차단하지만 문자열 차단으로 임의 명령의 안전성을 보장하지 않는다. 셸을 시작하기 전에 일시 중단 상태로 생성하고 Windows 작업 개체에 등록한 뒤 재개하며 종료 시 그 프로세스 트리를 정리한다. 외부 서비스나 예약 작업에 위임한 작업까지 되돌리는 기능은 아니다.

초기 버전은 비대화형 PowerShell이며 표준 입력은 닫혀 있다. 암호·토큰 입력, 관리자 권한 요청, 지속적인 REPL은 지원하지 않는다. 알려진 비밀 환경 변수 이름은 자식 환경에서 제외하지만 출력의 완전한 자동 비밀 제거는 보장하지 않는다. 비밀이 출력되는 명령은 승인하지 않아야 하며, 외부 API 사용 시 조회된 파일·셸 출력도 전송될 수 있다. Copilot과 비슷한 목록이나 호출 구조만으로 모델의 도구 선택 정확도가 보장되지는 않는다.
